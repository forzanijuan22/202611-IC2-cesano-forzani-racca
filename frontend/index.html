💧 IoT Campus — Sistema de Telemetría

Este dashboard SCADA permite monitorear y controlar en tiempo real el nivel de agua de un tanque equipado con un microcontrolador ESP32.

El sistema utiliza:

  • ESP32 con sensor ultrasónico JSN-SR04T para medir el nivel.
  • MQTT (Mosquitto) para comunicación en tiempo real.
  • FastAPI como backend para almacenar datos y servir la API REST.
  • SQLite como base de datos para el historial de telemetría.

Puertos del sistema:

MQTT Broker
Puerto 1883 (TCP)
MQTT WebSocket
Puerto 9001
Backend FastAPI
Puerto 8000 (HTTP)
Dashboard
Puerto 8000 (servido estáticamente)

📊 Panel principal

El dashboard muestra los datos del tanque actualizados en tiempo real vía MQTT:

  • Tanque visual: representación SVG animada con nivel de agua, burbujas y colores según el porcentaje (rojo <20%, cyan normal, verde >85%).
  • Métricas: cuatro tarjetas con nivel (%), cota (cm), distancia del sensor (cm) y estado de la bomba.
  • Gráfico histórico: gráfica con Chart.js que muestra la evolución del nivel y el estado de la bomba.
  • Estado del sistema: indicadores de conexión MQTT, API, cantidad de mensajes recibidos y uptime.
  • Registro de eventos: log en tiempo real de todas las acciones y mensajes.

🎛️ Controles

El panel de controles permite operar la bomba de agua:

  • Modo de operación: alterna entre AUTO y MANUAL con el toggle switch.
  • Modo AUTO: la bomba se enciende automáticamente cuando el nivel baja del 20% y se apaga al llegar al 85%. El botón de bomba se deshabilita.
  • Modo MANUAL: el botón "Encender/Apagar" se activa para controlar la bomba remotamente.

Los comandos se envían por MQTT al topic:

campus/tanque1/comando

Formato del mensaje de cambio de modo:

{"modo": "AUTO"} o {"modo": "MANUAL"}

Formato del mensaje de control de bomba:

{"bomba": "ON"} o {"bomba": "OFF"}

📋 Histórico

La sección de histórico consulta los registros almacenados en la base de datos SQLite a través de la API REST.

  • Filtros: puedes filtrar por cantidad de registros y estado de bomba.
  • Exportar CSV: descarga los datos visibles como archivo CSV para análisis externo.
  • Tabla: muestra ID, fecha/hora, nivel, cota, distancia, estado de bomba y modo.

📡 MQTT

El broker Mosquitto debe estar configurado con un listener WebSocket:

listener 1883 protocol mqtt listener 9001 protocol websockets allow_anonymous true

Topics utilizados:

Telemetría
campus/tanque1/telemetria
Comandos
campus/tanque1/comando

Ejemplo de payload de telemetría:

{ "porcentaje": 45.2, "cota_cm": 79.1, "distancia_cm": 120.9, "bomba": false, "modo": "AUTO" }

🔌 API REST

El backend FastAPI expone los siguientes endpoints:

GET /api/historial
Últimos N registros (?limit=100)
GET /api/ultimo
Última lectura registrada
GET /api/health
Health check del servicio
GET /docs
Documentación Swagger auto-generada

Ejemplo de prueba con curl:

curl http://localhost:8000/api/historial?limit=10

🔍 Solución de problemas

MQTT no conecta (WebSocket):

  • Verificar que Mosquitto tiene el listener WebSocket en puerto 9001.
  • Verificar que el servicio Mosquitto está corriendo con la configuración correcta.
  • Si usas firewall, asegurar que los puertos 1883 y 9001 estén abiertos.

No llegan datos al dashboard:

  • Confirmar que el ESP32 está conectado al Wi-Fi y publicando al topic correcto.
  • Probar con: mosquitto_sub -h localhost -t "campus/tanque1/telemetria"

API no responde:

  • Verificar que el backend está corriendo: python server.py
  • Probar: curl http://localhost:8000/api/health

Simular datos sin hardware:

mosquitto_pub -h localhost -t "campus/tanque1/telemetria" -m '{"porcentaje":45.2,"cota_cm":79.1,"distancia_cm":120.9,"bomba":false,"modo":"AUTO"}'
